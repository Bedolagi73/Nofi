# Nofi — сервис уведомлений по расписанию

Учебное приложение на C# и WPF для Windows. Оно планирует уведомления и имитирует отправку email и SMS. Результат и текст каждой подтверждённой попытки доступны в журнале.

## Запуск

Установите .NET 8 SDK и откройте терминал в папке с Nofi.csproj. Запустите приложение командой `dotnet run --project .\Nofi.csproj`. Команда сборки — `dotnet build .\Nofi.csproj -c Release`.

В разделе «Расписание» добавьте задачу и задайте получателя, текст, часовой пояс и расписание. Поддерживаются однократные, ежедневные, еженедельные и интервальные запуски. Календарное расписание вычисляется в часовом поясе задачи. Таблицы показывают время компьютера, а интервалы отсчитываются по UTC.

Пауза останавливает запуск новых попыток. Уже начатые попытки завершаются. После паузы или перезапуска пропущенная однократная задача выполняется сразу с отметкой о задержке в журнале. Для повторяющихся задач можно выбрать один догоняющий запуск или переход к следующему по графику.

## Повторные попытки

В лимит входит первая попытка. По умолчанию лимит равен трём, поэтому после двух временных ошибок задержка составляет 30 и 60 секунд. Общая формула — базовая задержка × коэффициент^(номер неудачной попытки − 1), с верхним пределом в один год. Постоянные ошибки завершают серию сразу. Ошибка неизвестного типа считается временной. Время уже запланированного повтора сохраняется при изменении настроек. Новый лимит проверяется перед следующей отправкой.

- Ожидает → Отправляется → Отправлено для успешной однократной задачи.
- Отправляется → Ожидает повтора → Отправляется после временного сбоя, пока есть попытки.
- Отправляется → Ошибка доставки после постоянного сбоя или исчерпания попыток.
- Повторяющаяся задача после завершения серии получает время следующего запуска. После неудачной серии статус «Ошибка доставки» виден до начала нового запуска.

Для ручной проверки в настройках можно включить заданную вероятность временного сбоя, ошибку для конкретного получателя или сбой на первых N попытках каждой серии. При нескольких включённых режимах сначала проверяется принудительный сбой, затем число первых сбоев, затем вероятность. Пример сценария с восстановлением — одна неудачная попытка, вероятность 0% и незаполненное поле принудительного сбоя. Тогда вторая попытка успешна. Задержка имитации задаётся отдельно в диапазоне 0–5000 мс.

Время, хранилище и каналы отделены от WPF. Расчёт расписания использует текущее время из `IDateTimeProvider`, а диспетчер принимает адаптеры `INotificationSender`.

## Хранилище и восстановление

Данные хранятся в `%LOCALAPPDATA%\Nofi`. Переменная окружения `NOFI_DATA_DIR` позволяет выбрать другую папку. Один каталог обслуживает один экземпляр приложения.

- `tasks.json` содержит задачи, настройки и пакет последних результатов, необходимый для восстановления журнала. Снимок заменяется атомарно.
- `journal.jsonl` содержит по одной записи на попытку. При превышении 10 000 записей журнал сохраняет последние 9 000. Фильтры доступны по задаче, результату и датам.
- `storage.lock` защищает данные от одновременной записи несколькими экземплярами.

После сбоя Nofi дозаписывает результаты из снимка по уникальным идентификаторам. Если процесс прервался в момент имитации и результата ещё нет в снимке, попытка возобновляется с тем же номером. Повреждённый снимок копируется в файл с суффиксом `.broken-*` перед созданием пустого списка задач. При повреждении журнала приложение сохраняет исходник и восстанавливает читаемые строки.
